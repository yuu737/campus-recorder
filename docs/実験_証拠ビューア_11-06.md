# 実験：証拠ビューア（Rerun）11/6

実装係（Claude Opus 5.5）、11/6 12:23〜12:40（PC の時計、約 20 分）。

## 何を見せるか
作品の売りは「寸法に根拠がある」こと。審査員と動画の視聴者に、次を 1 画面で見せる。

- **写真が模型のどこに立っているか**：登録済みの写真ごとにカメラ（四角錐）を置き、その先に縮めた写真（長辺 640 px）を小さく立てる。写真は模型に貼らない（カメラの位置に置く資料）。
- **どの目印が対応したか**：目印の一覧（`landmarks.catalog(lines=True)`、面ごとに色）を 3D の点と線で。目印係が指した対応は、カメラから目印への細い線（3D）。
- **再投影がどれだけ合っているか**：写真の 2D に、指した位置（赤）・解いた視点で目印を写した位置（水色）・その間の線と残差 px のラベル（黄、外れは桃色）・模型の面の線を写した物（薄緑）。
- **根拠の件数**：棟 JSON の measured／estimated／unknown の件数（全体・面ごと）を文書で。面の外周は、その面で一番多い状態の色（緑 実測・黄 推定・灰 不明）。
- **時間軸**：索引の `taken_at`（JST）で「撮影日時」と「撮影順」。再生すると撮った順にカメラと写真が増える。

カメラの色は登録の方法：橙＝目印の対応（landmarks）、青＝一括復元（sfm）、紫＝鎖（chain）、緑＝正面化と検収（rectify）。

## 作り方・開き方
```
.venv/Scripts/python -I -X utf8 -m recorder evidence data/buildings/honbu.json      # → out/honbu/evidence.rrd
.venv/Scripts/python -I -X utf8 -m recorder evidence data/buildings/tower75.json    # → out/tower75/evidence.rrd
.venv/Scripts/rerun out/honbu/evidence.rrd                                          # 既定は 3 枚組の画面
.venv/Scripts/rerun out/honbu/evidence.rrd out/honbu/evidence_overview.rbl          # 画面を替える（overview／photo）
```
オプション：`--photos id,...`（写真を絞る）、`--no-images`（画像を入れない）、`--long-side 640`、`--out`。
所要は 1 棟 5〜10 秒（.rrd は本部棟 2.6 MB、タワー75 8 MB。大半は模型の glb）。

画面（ブループリント）は 3 つ。`.rrd` には 3 枚組が既定として入っている。
| ファイル | 中身 | 用途 |
|---|---|---|
| `evidence_three.rbl`（既定） | 左：3D 全体／右上：選んだ写真の 2D（目印と再投影）／右下：根拠の件数、下に時間軸 | 動画の基本の画面 |
| `evidence_overview.rbl` | 3D 全体（別の向き）＋根拠の件数 | 引きの絵 |
| `evidence_photo.rbl` | 写真の 2D を大きく＋根拠の件数 | 再投影の寄り |

2D に出す写真は、使われた対応が 6 点以上の登録のうち再投影 RMS の一番小さい物（本部棟は P223、タワー75 は PXL_20261105_061449185）。時間の印は「最後に合わせる（following）」で始まるので、開いた時は全部の写真が出ている。動画では時間軸を左端に戻して再生すると、撮った順に増える。

## Web で見せる方法（確かめた事）
- `rerun --web-viewer --web-viewer-port 9095 <rrd>` でブラウザの Rerun が立つ（HTTP 200、ローカル）。
- **Web 版のビューア（Rerun 0.42 の Web 版）は `?url=<.rrd の http の URL>` で .rrd を読み、既定の 3 枚組の画面で開けた**（ブラウザの画面で確認：CORS を付けたローカルの静的サーバ http://127.0.0.1 から）。
- したがって、`.rrd` を **CORS が付く静的な置き場（GitHub Pages は `Access-Control-Allow-Origin: *` を返す）** に置けば、
  `https://app.rerun.io/version/0.42.0/index.html?url=https://<user>.github.io/<repo>/evidence.rrd` のリンクだけで審査員が開ける見込み。
  - 公開の app.rerun.io からローカル（127.0.0.1）の .rrd は読めなかった（ブラウザが https → ローカルの通信を止める。公開の置き場なら当たらない）。
  - **実際に GitHub Pages に置いて開くのは未確認**（公開は利用者の判断）。ビューアの版（0.42.0）と .rrd を作った SDK の版を揃えること。
  - 置く前に、写真（640 px に縮めた物）に人の顔・車のナンバー・研究室や貼り紙が写っていないか見る（規約 4・6）。期間前の写真（本部棟 P223）も入るので、外すなら `--photos` で期間中だけにする。

## ライセンス
- Rerun SDK（`rerun-sdk` 0.42.0）：MIT／Apache-2.0 のデュアル。依存で `pyarrow`（Apache-2.0）が入った（opencv は入れ直していない）。
- Web 版のビューア（app.rerun.io）：同じく MIT／Apache-2.0。

## 限界
- Rerun 0.42 の glTF 読み込みは `KHR_texture_transform` に対応しないので、読み込む時に glb からこの拡張を外している（`strip_gltf_extensions`。形は同じ、質感の繰り返しの倍率だけが Web 3D と違う）。glb そのものは触らない。
- 面の外周の色は「その面で一番多い状態」。今はほぼ全部の面が推定（黄）で、実測の少なさがそのまま見える（隠さない）。
- 写真に写す模型の線は、台帳の「見えている面」の線だけで、隠れ（手前の面に隠れる線）は消していない。
- 目印の番号は一覧が増えると振り直される（本部棟の 11/6 朝の登録は窓の段を足す前の番号）ので、対応は「同じ面の同じ名前」で照合している。名前が無い古い対応は番号で引く。
- 撮影日時の表示は UTC（例 06:23Z ＝ JST 15:23）。ビューアの設定で現地時刻に替えられる。
- 鎖・正面化・SfM の登録には目印の対応が無いので、2D には模型の線の重ね合わせだけが出る。
- `rerun-sdk` は requirements.txt に入れていない（任意の道具）。
