## 1. 前作の全体像

- **何を**：天白キャンパス全体（建物・道路・階段・地形、一時は 15 棟 88 階の内装まで）を 3D にし、Web で歩けるようにして公開した（`meijo-3d-unofficial.yuustudio.app`、Cloudflare）。
- **どの道具で**：Blender 5.2（Cycles で光を焼き込み）＋ Python。Web は Three.js・camera-controls・Rapier（当たり判定）・React・Vite。配信の軽量化に glTF Transform・meshoptimizer・KTX2・xatlas。重い計算は Modal／Kaggle のクラウド GPU。AI は 8〜10 月上旬 Codex、10/10 から Claude Code。
- **どこまで**：Web で 8 地点への移動・ジャンプ・当たり判定つきの歩行まで公開。ただし配信は標準画質で 672 MB（10/29）と重く、遠景 LOD は試作止まり。モデルは Blender 上で 1 つの巨大なファイル（約 1.8 GB）を手で直し続ける方式で、「どの寸法に根拠があるか」は最後まで台帳にならなかった。
- **一言で**：前作は「見た目を Blender で作り込み、それを Web に重いまま運ぶ」作品。今の作品は「根拠付きの JSON から軽く生成する」作品。Web の技術の多くは、前作の**重さを運ぶため**の物なので、今は要らない物が多い。

## 3. 「入れる」の順番と実装の要点

考え方だけ。前作の関数名・コードは使わない。

### ① 公開 URL と出典の表示（半日、利用者の許可が要る）
- `web/` を静的ファイルとしてそのまま公開する。前作の失敗に従い、**生成物を GitHub に入れて自動ビルドさせない**（`web/data/` は git 管理外のまま）。手元で `export-web` → 直接配信、の 1 本道にする。
- 1 ファイルの上限（前作の配信先で 25 MiB）を超えないか、公開前に大きさを確かめる。今は最大 4.6 MB（tower75.glb）で余裕。
- three.js は jsdelivr から読んでいるので、版を固定したまま（0.170.0）でよい。
- 画面の隅に出典（OpenStreetMap の寄稿者、PLATEAU、国土地理院、CC0 素材の作者・Poly Haven）を出す。OSM は表記が必須。
- 「非公式」と名前に入れる（前作は公式と誤解されないよう途中で名前を変えた）。
- 巻き戻しは配信先の版の履歴で行う。手元のファイルを戻しても公開は戻らない。

### ② 建物で止まる・基壇と階段に上がれる（半日）
- 止まる：`site.json` の各棟の足元の多角形に入りそうになったら、その辺に沿って押し戻す（2 次元の判定。物理エンジンは使わない）。設計済み棟は外壁の輪郭、未測の箱は PLATEAU の輪郭。
- 上がれる：glb の中で「歩ける面」（基壇の上面・階段・玄関の床）にだけ下向きのレイを当て、地面の高さと大きい方を採る。段差の上限（例 0.4 m）を超える所は登れない＝壁と同じ扱い。
- **床・壁の区別は名前の規則にしない**。前作は日本語名が規則から漏れて歩けない所が出た。製図の段階で、JSON の部品の種類（steps・podium・entrance など）から glb の各物体に「歩ける／壁」の印（glTF の extras）を書き、Web はその印だけを見る。
- 簡単な検査を足す：移動先ボタンの開始位置が建物の中に入っていないか、足元が見つかるか（前作の「8 地点・72 条件」の小さい版）。

### ③ スマホで落ちない・実機で触る（半日）
- 自動の画質切替は**作らない**（前作で逆に落ちた）。タッチ端末は最初から軽い設定：画素密度 1.5 以下、影 1024 px か影なし。画面に「軽量／標準」の切替ボタンを 1 つ。
- WebGL の文脈が失われたら、黒画面で止めず「表示が止まりました・軽量で開き直す」を出す。
- `?stats=1` で FPS・描画回数・三角形数を画面の角に出す。実機で 3 分歩いた結果を `docs/日誌.md` に残す（前作は最後まで「実機の性能確認ではありません」のままだった）。
- スティックは実機で、指を離した時・画面の外に出た時に止まるかを確かめる。

### ④ Web の見え方も検収する（半日）
- `web_cameras` の視点ごとに、Blender の描画（`persp_street.png` など）と Web の描画（`?cam=…&ui=0`）を自動で撮って並べる。
- Web 側の画像で「ほぼ真っ黒の塊」「空が抜けて見える所（面の裏返り・欠け）」「地面との間の隙間・めり込み」を探し、**場所と部品の名前の一覧まで**を出す。直すかどうかは検収係（Claude）が JSON を見て決める。数値の合格を目的にしない（前作の教訓）。

### ⑤ 根拠の色で見る（半日〜1 日）
- 製図の段階で、glb の各部品に棟 JSON の状態（measured／estimated／unknown）と根拠の写真番号を印として書く。
- Web に「根拠で見る」切替を足す：measured は実際の材質のまま、estimated は薄い黄、unknown（または仮置き）は斜線・赤。部品をタップすると「根拠：写真 #12、方法：正面化＋周期」が出る。
- 前作の考え方を借りる所：**「形がある割合」と「根拠がある割合」を別々に出す**。棟の札に「形 100%・根拠 measured 62% / estimated 30% / unknown 8%」。estimated を形として出すので、前作のような「根拠が無いから描かない → 模型が退化」にならない。
- 動画の決め絵になる：普通に歩く画面 → ボタン 1 つで根拠の色 → 赤の所に「撮影依頼」が出ている、の流れ。

## 4. 「要らない」の理由（まとめ）

1. **重さを運ぶための技術は、今は運ぶ重さが無い**：区画読み込み・LOD・量子化・gzip・KTX2・クラウド GPU は、672 MB〜1.6 GB の配信のための物。今は 10 MB 弱。
2. **前作で失敗して自分で捨てた物**：自動画質切替（落ちる）、光の焼き込み（黒い壁の最多原因）、先読み。
3. **規約に触れる物**：Google の 3D メッシュ、CC BY の木、公式平面図をなぞった内装、研究室の点群。
4. **範囲の外**：内装、周辺建物の作り込み、更新通知・リリース管理（見る人が少なく公開も数回）。
5. **もう今の作品にある物**：写真の視点の逆算（検収 B）、材質の焼き込み、昼光と空、移動先ボタン、視点 URL。

## 5. 前作の反省で、今の作品が同じ轍を踏みそうな物

前作の「失敗と対応策」（`名城3D_制作履歴まとめ.tex` 6 章）と引き継ぎ書から。危ない順。

1. **根拠を厳しくしすぎて模型が退化する**（8/24）。前作は「根拠の無い所は形にしない」規則でモデルが退化し、同じ日に撤回した。今の規約 5（測れなければ unknown）は正しいが、残り 4 日で写真が足りないと、図書館・11 号館が灰色の箱のまま動画に映る。→ estimated（方法と根拠付きの推定）を正しく使い、unknown の所は「撮影依頼の札」として**見せる**（⑤）。unknown を隠すのではなく、作品の特徴にする。
2. **スマホの実機で一度も触らずに出す**。前作は端末の模擬（390×844）までで「実機の性能確認ではない」と書いたまま公開した。今もエミュレートのみ。影 2048 px・画素密度 2・HDRI の PMREM は、古いスマホで落ちうる。審査員はスマホで開く。→ ③。
3. **自動の検査は合格なのに見た目が不合格**（8/31、9/12）。pytest 38 件が通っても、Web で地面に浮く・めり込む・黒い面は分からない。今の検収は Blender の描画と写真の比較で、Web の見え方は対象外。→ ④。特に、Web の地面（4 m 格子）と glb の足元（ground_z）の食い違いで、建物の足元が浮く・埋まるのは前作の「浮き・食い込み」と同じ形。
4. **床・壁を名前の規則で決めて漏れる**（10/21）。日本語名の部材が床と認められず歩けなかった。→ ② で、名前ではなく JSON の部品の種類から印を付ける。
5. **公開の手順で古い版に戻す・大きなファイルで失敗する**（10/21、10/26）。→ ① で、生成物は git に入れず直接配信、公開前に大きさを確かめ、公開後に URL で実物を開いて確かめる。
6. **文書が積み重なり、最新を取り違える**（8/24、8/30、10/10）。今も `docs/11-03_やること.md`・`11-04_やること.md`・`逆算.md`・`勝ち筋.md` と増えている。→ 引き継ぎは 1 枚の先頭に最新を書く。文書より実ファイルの更新日時を優先。
7. **オーバーエンジニアリング・版の乱発**（9/2〜9/12）。細かい検査・報告に時間を使った。→ 「後回し」の物（変異試験・LOD・焼き込み）に手を出さない。
