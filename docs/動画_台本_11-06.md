## 2. 収録の手順

1. **画面**：1920×1080、Windows の表示の拡大 100%。通知を切る（集中モード）。Edge は F11 で全画面。エディタ（#9・#10・#14）は文字を 20 px 以上に拡大し、見せる行だけ折りたたまずに出す。
2. **録画**：OBS（キャンバスと出力 1920×1080、30 fps、記録は mkv→mp4 に再多重化）。OBS が無ければ Windows の Game Bar（Win+Alt+R。1 つのアプリの窓だけ録れる）。ナレーションは別に録って編集でのせる（読みの速さは 1 秒 6 字が目安。60 字のカットは 10 秒）。
3. **配信**：`.claude/launch.json` の `root`（8766）でリポジトリ直下を配信し、歩く画面は `http://localhost:8766/web/index.html?cam=…`、報告は `…/out/honbu/report.html`。#4 の職員の画面は `recorder serve` が要るが、既定のポートも 8766 なので **root を止めてから serve を起動**（または serve を別のポートで）。
4. **歩く 10 秒（#15）**：`?cam=-47.42,-58.51,45.50,27.80,13.40,77.57`（`out/honbu/model_report.json` の `web_cameras.street`）で開き、ドラッグで向きを変えて W で前へ。速さを一定に、急に振り向かない。3 回録って一番なめらかな物を使う。タワー75 の構図は `cam=-0.11,44.86,44.50,117.63,37.30,77.57`。
5. **静止画のカット**は、編集ソフトでゆっくり寄る（2〜3 秒で 110%）だけ。絵そのものは直さない（生成物を手で直さない決まり）。
6. 終わったら headless の Edge と Rerun を閉じる（GPU を掴み続けるため）。

## 3. 代案：API の通し実行が間に合わなかった時

嘘をつかずに、何が自動で何が手かを分けて言う。#4・#8 のナレーションを次に替える。

- #4：「写真を落とすと、受付が棟ごとに係の順番を組みます。／今回の試走では、その係を／Claude Code の中で順に呼びました。」（テロップ：試走は係を手で順に回した）
- #8：「係は同じ指示書で動き、API でも／同じ順で呼べるようにしてあります。／決めるのは Claude、測るのはコード。」
- 言ってよい事：受付（`recorder serve`）と順番（`run_pipeline`）はある、キーが無い時は送る内容を作るところまで（dry-run）確かめた、図面・模型・報告は係の出力から自動で生成された。
- 言わない事：「ボタン 1 つで全部自動で出来た」「職員が撮ってすぐ 3D になった」（通していない物を通ったように言わない）。#4 の画面に dry-run の文字が出たら、隠さずテロップで「試走（API キーなし）」と書く。
- 通しが間に合った時は、#4 のテロップに実際の所要時間（`out/<棟>/serve_<日時>.json`）を入れる。
