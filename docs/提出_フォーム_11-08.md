## 3. プロジェクト概要（必須）

**採用：案 B（誰＝遠くの受験生）。フォームには案 B の枠の中をそのまま貼る。**（11/8 18:30 の指示書 4 節で決定。案 A は採らなかった案として残す。）1 文目はテーマ「本来、誰にでも届くべきものを。」に合わせた（届けられない／届く）。

### 案 A（誰＝大学の職員）※採らなかった案

```
このプロジェクトは、大学の職員の「予算も3Dの専門家も無く、来られない受験生にキャンパスの姿を届けられない」課題を、スマホで撮るだけでClaudeの係が根拠付きの建物を起こし歩ける3Dに足していく流れに変える、記録と引き継ぎの道具です。

建物1棟の3Dの外注は約4万〜100万円で、測る作業は別です。場面の例：職員が本部棟の正面にメジャーを当てて撮り、職員の画面から送ると、撮影係（Haiku）が数秒で使えるかを返します。仕分け・測量・設計の係（Opus）が写真を見てどの面か・柱が何本か・どの物差しを信じるかを決め、計算はコードが行います。値はすべて写真番号つきの実測、方法を書いた推定、空欄のどれかです。模型を写真に重ねて確かめると歩く画面の灰色の面に色が付き、測れない面は灰色のまま「坂の下から面全体が入る1枚をください」と撮影依頼が返ります。行き詰まると進行役の係が決めて続け、職員は後で承認か取り消しをします。本番では本部棟の柱間5.310 mを、メジャーと数えたタイル46枚から実測にしました（長さの実測はまだ2件）。棟のJSONと撮影依頼ごと次の担当へ引き継げます。
```

## 7. 開発中に一番詰まった場面（必須）

**選んだ物：本番で指示役の Claude が相談なしに決定を書いて再開し、調べると製品の中の進行役が工程の輪から一度も呼ばれていなかった（11/8 09:36〜12:16、K-205〜208 → K-301）。**
選んだ理由：Claude の挙動に直接関わり、対処が具体（自動の進行役・事前の点検）で、決定ファイルと日誌に時刻つきで残っている。

### 何を作ろうとしていたか
写真を送ると係（Claude のエージェント）が自動で測り、設計図を書き、歩く画面まで人の手なしで進む流れ。11/8 は本部棟の追記（メジャー写真を足して柱間を実測にする）を、API で動かす本番として回していた。行き詰まり（事件）の時は進行役の係が決める設計だった。

### Claude にどう指示したか
事件で止まったら、指示役（Claude Code の Opus）が利用者か進行役（Fable）に相談して決定を書き、再開する、という進め方で頼んでいた。1 つ目の事件（05:25）はこの形で Fable に相談し、決定 K-201〜204 で測量からやり直した。

### 何が起きたか・期待と何が違ったか
09:35 の 2 つ目の事件（再検収 2 回で不合格の面 4）で、指示役の Opus が利用者にも Fable にも相談せず決定 K-205〜208 を書き、09:36 に再開した。利用者が止めた。調べると、進行役の係は定義と費用の枠があるのに工程の輪から一度も呼ばれず、事件を書き残して止まるだけだった。「事件は進行役が決める」は手順書の上だけで、実際は人が CLI で決定を渡していた。

### どう対処したか
K-205〜208 は案のまま取り下げ、記録を 09:35 に戻した（`scripts/rewind_honbu_k205.py`）。利用者と Fable が決め（K-301）、Opus の係が「事件が出たら道具が進行役を自動で呼び、決定ファイルで同じ記録のまま再開、3 回まで、4 回目は人」と職員の画面の承認／取り消しを実装した。押す前に審査員役（Opus）が落ちる筋 16 件を挙げ 13 件を直し、点検 `recorder agent preflight` が「Invalid API key」を捕まえた。11:33 の人の操作 1 回で、12:16 に歩く画面まで届いた。
同じ日の夕方、0 からの実走でも製図が 4 回止まり、人が決定を 1 回手で入れた。コードの失敗では進行役が呼ばれない穴が残っている。

出典：`docs/日誌.md` 11/8 04:13〜09:36・10:05〜12:16、`data/reports/指示_11-08/決定_本番_3.md`（K-301〜303）、`data/reports/指示_11-08/決定_自動_honbu_1.md`（K-401〜405）、`docs/Claude活用の記録.md` 7 節、`data/reports/honbu/jisseki_20261108.md`。末尾の 2 行は 0 からの実走の記録 `D:\BuiltwithClaude_run0\out\honbu\pipeline_state.json`（製図 seizu が 17:30:09・17:30:39・17:31:04・17:32:17 に失敗、17:35:08 の再開で通過。再開の理由は 4 回とも `code`、`shinko: false`）と `D:\BuiltwithClaude_run0\data\decisions.json`（D-0001、17:34:43、「利用者の判断で書いた」）。

### 他の候補（差し替える時用）
1. **SDK の 1 通の上限で係が落ちた（J-101、11/8 03:12）**：撮影係（Haiku）が写真を Read した結果が 1 通 1 MB（1048576 bytes）を超え、`CLIJSONDecodeError` で落ちた。`max_buffer_size` を 32 MB にして直した。止まった呼び出しの費用が合計に入らない不具合（J-103、道具の記録 0.48 USD／API 画面 1.51 USD）も同時に見つかった。製品は Agent SDK、原因は「API・外部連携」か「セットアップ」。出典：`data/reports/指示_11-08/詰まり_本番.json`。
2. **使用量の上限で疑似本番が約 2 時間 55 分止まった（J-014・K-004、11/7 10:58 頃〜13:53）**：4 棟を同時に回していて 5 時間の上限を使い切り、係 4 本が落ちた。SendMessage で同じ会話の続きから再開し、本番用には 429 から自動で続きから再開する仕組みを入れた。製品は Claude Code（サブエージェント）、原因は「使用量の制限」。出典：`data/reports/疑似本番_11-07/結果.md`、`docs/Claude活用の記録.md` 2 節。
