何も知らない Claude（Opus）4 人に、大会の説明・作品の中立の要約・規約 1 番・物差し台帳・今の数字（長さの measured 0 件、メジャー写真 68 枚が来た事、タイル共通の申告）・測量の流れ・本部棟 f6 の値の実例 6 件だけを渡し、審査員として採点させた。リポジトリは読ませていない。4 案は同じ数字で「状態の付け方」だけが違う。4 人には案を違う順で「案 1〜4」として渡し、どれが誰の案かは書いていない。資料は作業用の一時フォルダ（scratchpad/judge/judge_1〜4.md）に置き、リポジトリには入れない。

背景：11/7 15:05〜15:40 に職員（作者）がメジャーを壁に当てた写真を 4 棟で 68 枚撮った。利用者の問い「根拠をたどった先にメジャーがあるなら measured では？」に対し、Fable は「たどる途中の輪が全部、写真で測った物であること」を条件に付ける案を出した。どちらが審査員に通るかを見るための採点。実装はまだしていない。

## 4 案
- **A 今の決まり**：メジャーと同じ写真・同じ面で直接測った区間だけ measured。周期を別の写真の枚数に掛けた時点で estimated
- **B 鎖の全輪が写真で測った物**：①メジャーの目盛りの読み ②写真から数えた個数 ③同じ面を正面化した画像の px 比、のどれかだけで鎖がつながれば measured。目視の比率・仮定・公開資料・典型値が入れば estimated。± は輪ごとに積み、鎖を JSON に書く（Fable の案）
- **C 先にメジャーがあれば measured**：途中の輪は目視の比率や「同じタイル」の申告でもよい（利用者の問いを広く取った物）
- **D 3 段**：measured（A の直接）／derived（B の鎖）／estimated。図面・歩く画面・集計を 3 色で

## 案ごとの赤旗（審査員の言葉の要約）
- **A**：「メジャーを 4 棟で当てたのに長さの measured がほぼ 0 件。なぜ測ったのか」（4 人全員）。正面化の px 比（例 4）と目分量（例 4'）が同じ estimated になり、根拠の強さの差が消える（2・3）
- **B**：「メジャーを当てた場所の周期が面の全体でも同じ」という前提が輪として書かれていない。例 6 で外した「同じタイルという仮定」と本質は同じ種類なのに通している。基準が一貫していない（全員）。24 枚 × 周期は直接測っていない区間の外挿で、measured と呼ぶのは言い過ぎでは（1）
- **C**：例 6（図書館で 1 cm も測っていないのに申告＋目視で measured）。ここを 1 件突かれると measured の数全体が信用を失う（全員）。規約 1 番と 5 番の趣旨に反し「安心してそのまま使える」と言えない（2・4）
- **D**：規約 1 番の「3 つのどれか」に期間の終盤で 4 つ目を足すことになる。変えた日と理由を書かないと「数を良く見せる新しい箱」と突かれる（1・2・4）。derived は B の measured の言い換えで、見出しの「measured は数件」は変わらない（3・4）。検証・図面・歩く画面・集計を全部直す範囲が広い（3・4）

## 4 人が共通して言ったこと
- **検算は 6 例とも合っている**。ただし例 4（px 比）に ± が無い。「輪ごとに積む」と決めた案で ± の無い measured は検証で落とせ
- **± に、枚数の数え違い（±1 枚＝約 4%）と正面化の px の誤差を入れろ**。メジャーの読みだけでは小さすぎる
- **「同じ面では周期が一様」を鎖の 1 輪として明記しろ**。確かめ方：面の別の場所でもう 1 回メジャーを当てた写真で検算（3）、検収係の重ね合わせのずれを添える（1）
- **集計では「直接測った区間」（A の意味の measured）を内訳として分けて見せろ**。長さの measured と個数の measured も分ける。数を盛ったと見られないため（2・3・4）
- 「メジャーを 1 枚撮れば measured に変わる」が撮影依頼と直につながるのが、B・D の一番の評価点（全員）

## 進行役（Fable）の読み
- **C は採らない**（全員一致、理由も同じ）。「根拠の先にメジャーがあれば」は、途中の輪が目視や申告でも通ってしまう点で、規約 1 番を自分で崩す
- **A も採らない**。68 枚を撮った成果が数字に出ず、px 比と目分量の差も消える
- **B と D は同じ物**で、審査員が突くのは「4 つ目の状態を足した説明」（D）か「盛ったと見える」（B）のどちらか。両方を避ける形は、**状態は 3 つのまま（B）、根拠の欄に `kind: direct | chain` の内訳を持たせ、集計・図面・README で「直接測った区間 n 件／鎖で measured m 件」を分けて見せる**。規約 1 番は変えず、D の見え方だけ取る
- B を採る時の条件（審査員の条件をまとめた物）：
  1. 「同じ面で周期が一様」を鎖の輪として書く。根拠は、正面化した面の全体で自己相関の周期（px）が一様であること（数で書く）か、面の別の場所のメジャー写真での検算。どちらも無ければその面は estimated
  2. ± は、メジャーの読み（±0.5 cm ÷ またがった枚数）＋ 数え違い（±1 枚 × 周期）＋ 正面化の px の誤差、を輪ごとに積む。± の無い measured は検証で落とす
  3. 鎖（輪の種類・写真 id・px・枚数・±）を棟 JSON に書き、検証は各輪に写真 id があるかを見る。目視・申告・公開資料・典型値の輪が 1 つでもあれば estimated
  4. 集計と README で、直接／鎖／個数の measured を分けて出し、縮尺の付け替えで値が何 % 動いたかを前後の件数と共に書く（11/6 の模擬採点の指摘と同じ）
