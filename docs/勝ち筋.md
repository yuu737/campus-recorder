# 勝ち筋（入賞に必要な条件から逆算する）

2026-11-03 作成。計画（11-03_やること、日誌の日程）は手段で、これが目標。日程はここに合わせて何度でも組み替える。

## 1. 審査の仕組みから分かる「勝つ条件」

- 配点：**インパクト 30／デモ 25／Claude の活用 25／深さと実行 20**
- 一次審査（11/9）の後、**上位6チームの3分動画をそのまま流して**決勝（11/10）。審査員は各作品に約2分話すだけ。
  - つまり **動画が作品**。リポジトリは「動画が本当か」を確かめる裏付け。
- 受賞5作品に共通していたこと（参考資料 06）：
  1. 最初の10〜15秒で「誰が、何に困っているか」を言い切る
  2. 作者本人が当事者
  3. 機能を並べず、1人の人物の流れで見せる
  4. 「なぜ今の Claude でできるのか」を一文で言う
  5. 仕組みは30〜40秒、図と数字で
  6. 本物の手応えを1つ入れる（市長の声、娘が使った、店で試した）
  7. 見せ場は**目に見える変化の瞬間**（LED が光る、基板に手順が描かれる）
  8. 大きな見通しの一文で締める

## 4. 必達と優先順位（配点順）

1. **本物の手応え**：先生か職員が1面を撮って、道具が返事をし、3D が増える場面を撮る。日程の都合で 11/7。相手を今日のうちに決めて頼む
2. **見せ場の4段の変化が1本で通ること**（本部棟1棟）：写真 → 速い返事 → 図面 → 3D → 重ね合わせ → スマホで歩く。これが無いと他の全部が無意味
3. **見た目**：素材（JSON の寸法からパターン生成＋Polyhaven CC0）、地形、道路、木。前のモデルの Google 抜きの水準を Z09 全体で目指す。上限は写真の枚数
4. **数字**：写真・寸法・未確定・撮影依頼・検収回数を道具が自動で数えて出す（README と動画で使う）
5. **Claude の活用の一文**と、エージェントの構成図

## 5. やらないこと

- どの大学でも動く一般化（入力欄は置く、中身は天白固定）
- Blender の中での手直し（直すのは JSON。検収係 Claude が判断する）
- 数値の厳密さを見た目より優先すること。±5% は「重ねて目で分からない」の目安で、目的ではない
- PLATEAU だけで完成とすること
