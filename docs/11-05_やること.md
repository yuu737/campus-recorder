### 写真の使い方の方針（11/5 03:12 に Fable が出し、利用者は異論なし。道具の 1 節）
写真は「読む物」ではなく「模型を当てはめる相手」にする。
1. 先に全部の写真の視点を決め、それから全部をやる（登録を工程の最初に）。仕分け・観察・数えも生の写真でなく「面に展開した画像」や「模型に貼った画像」の上で読む（画素→m が済んでいるので AI の目視の誤差が減る）
2. 寸法は 1 枚から読まず、全写真で当てはめる。部品のパラメータを少し動かして全写真の縁との一致を最大にする自動の当てはめ（再検収の線の照合を目的関数に。約 1 日）。検収係の判断は「どの部品を疑うか」と「取り違えの除外」に減る
3. 写真の役割を 5 つに分け（面の正面・横にずらした連続・部品の寄り・斜めの検収用・質感）、値ごとの誤差幅から撮影依頼を自動で出す（被覆図の延長、約半日）。これが「記録して引き継ぐ」の肝
4. 輪郭を使う：空との境（パラペット・塔・庇）、地面との接線、航空写真の影は 1 枚でも高さが決まる
5. 質感は写真を貼らず、写真から値を取る（タイルの色は日陰の写真で較正、ガラスは共通の素材、光は HDRI）

やらない：写真を最終の質感に貼る、LLM に生の画素を読ませて寸法にする（11/3 で失敗済み）、GPS を根拠にする。

## 11/5 午後に用意した仕組み（試行はしていない。利用者の指示「仕組みだけ用意」）
- **進行役 `shinko`（Fable）**：部品ごとの審判ではなく、6 つの事件（立ち上げ・行き詰まり・語彙・アセット・完成判定・人を呼ぶ）の時だけ呼ばれる。決めた事は規則にして手順書に足す。検出は `recorder agent events <棟>`／`--site`（`out/<棟>/events.json`）。`agent pipeline` は stuck/vocab/asset で止まる。モデル `claude-fable-5-1` を API の対応表に追加
- **置く係と止める係**：設計係は「観察票の 1 m 以上を全部置く」だけ。検収係が止める役を兼ね、止める理由は 5 つだけ（「寸法が無い」は不可）。争点は `out/<棟>/soten.json`、規則で決まらない物だけ進行役へ
- **立ち上げ**：`recorder campus init <slug>` → 地図探し係 `chizu`（Haiku、公式サイトの地図の URL・日付・棟名だけ。画像は保存しない）→ `site build` → 進行役が `name_links`（地図の棟名 ↔ 足元。名称・有無・位置だけ）と `scope.targets`（範囲）→ `recorder campus check`。名城固有（棟名と id の対応・既定のキャンパス・PLATEAU の在りか）はコードから敷地 JSON `data/site/tempaku.json` に移した
- **職員の振り分け**：`web/staff.html`（静的。棟・外観/内装・階の 3 つだけ。写真は端末から出さない）→ `assignments.json` → `recorder photos assign --from`。索引に `assigned_by`・`interior`・`floor`・`assigned_at`。職員の値が勝ち、GPS は検算。仕分け係は面だけ
- **棟をまたぐ物の置き場所**：1 棟の壁に付く→棟、2 棟か間の地面→敷地 JSON、不明→争点。敷地に置く語彙はまだ無い（道具の穴）
- **敷地の検収係 `shikichi`（Opus）**：地面の帯の重なり・基準の地面・橋の両端・足元の重なり・航空写真を数字で。直すのは各棟の検収係。帯が重なった時の決まりは未実装
- **本番の API**：係は Opus/Haiku、事件で Fable。語彙を足す決定はコードの変更なので「人が見てから入れる」と README に書く
- 試していない物：進行役を実際に呼ぶ、立ち上げを他大学で、staff.html のブラウザ表示、`campus check` の実物の結果
