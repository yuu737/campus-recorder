### なぜ本体の .venv の python を直接使わないか
本体の .venv には recorder が「編集可能な取り込み」で入っていて、`python -I` で動かすと **どこで動かしても本体の
`D:\BuiltwithClaude\recorder` を読む**（そのコードは自分の場所から data/・out/ を決めるので、本体の data/ に書く）。
serve が係の道具を起動する時も、係が道具を打つ時も `-I` なので、作業ツリー専用の .venv を作った。
→ **必ず `D:\BuiltwithClaude_run0\.venv\Scripts\python.exe` を使う。** 確かめ方：
`.\.venv\Scripts\python.exe -I -c "import recorder; print(recorder.__file__)"` が `D:\BuiltwithClaude_run0\recorder\__init__.py`。

## 1. 鍵を入れた端末で serve を 8768 で立てる（端末 A）
**8767 は本物の data の serve。触らない。**

16:10 からは 1 と 2 を 1 本にした起動の道具を使う（鍵を 1 回だけ入れる。recorder の場所・BLENDER を確かめ、
`preflight --call-models --no-serve` で 4 モデルを呼び、「記録が無い」以外の落ちる物があれば serve を立てずに止まる。
点検の結果は鍵を除いて `out/run0_preflight.json`）。道具は準備係のスクラッチ（リポジトリの外）の `start_run0_serve.py`：
`& 'D:\BuiltwithClaude_run0\.venv\Scripts\python.exe' -I -X utf8 <scratchpad>\start_run0_serve.py`
以下は手で打つ時の元の手順。
```powershell
cd D:\BuiltwithClaude_run0
$s = Read-Host "API キー" -AsSecureString          # 画面にも履歴にも残らない
$env:ANTHROPIC_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringUni([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))
$env:BLENDER                                        # Blender 5.2 のパスが出る事を確かめる（無ければ入れる）

```

## 5. 押す
棟 JSON が無い棟は、職員の画面に「写真を入れずに始める」ボタンが出ない（写真をもう一度入れる道しか無く、取り込みし直しになる）。
ボタンと同じ受付（`POST /api/start`、上限 40 USD）を端末 B から 1 回だけ叩く：
```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8768/api/start -ContentType "application/json" -Body '{"buildings":["honbu"],"max_usd":40}'
```
返事の `modes.honbu` が `new`、`dry_run` が `false` である事を見る（`true` なら端末 A に鍵が入っていない → serve を止めて 1 から）。
事件の決定は製品の中の進行役が自動でする（K-301）。人は職員の画面で事後に承認／取り消すだけ。

## 6. 打ち切り（利用者が決めた時だけ）
時刻では切らない。利用者が打ち切ると決めたら、撮影は端末 C で Ctrl+C。記録がまだ走っていたら：
1. やわらかく（今の工程が終わってから止まる。端末 B）：
   ```powershell
   .\.venv\Scripts\python.exe -I -X utf8 -c "from recorder import agents; print(agents.request_halt('honbu', '利用者の判断で打ち切り', cwd='.'))"
   ```
2. 待てない時：端末 A で Ctrl+C（serve ごと止まる。記録は running のまま残り、10 分後に stale 扱い）。
3. 止めたら端末 A・B を閉じる（鍵はそのタブの中だけ）。
