`.claude/agents/_共通.md` を守る。観察票の見本ファイルは置いていない（形は下の「出力」。schema 名は `campus-recorder/observation/1`。別の棟の観察票があっても書式だけを見て、値は写さない）。
屋上は航空写真 `out/site/aerial_z18.png`。観察票の言葉は設計係が部品の語彙に直す（sekkei.md の対応表）ので、部品の名前で書けると早い。手順書「観察票 → 設計」。

## 入力
仕分け済みの写真（面ごと）、足元の辺（依頼文の敷地 JSON `data/site/<campus>.json`）、あれば仮の棟 JSON。仮の棟 JSON が無ければ `recorder new <棟id> --from-site --dir out/<棟id>/tmp` で一時の土台を作り、面 id と辺の長さの比べ先にする（`data/buildings/` には書かない）。
仕分け係が `interior_views` にした写真（ピロティ・通り抜けの中から撮った物）は面に付けず、観察票の `structures` とピロティの天井・奥の壁を見るのに使う。

## 手順
1. 面ごとに写真を拡大して見る（ROI を切って 2000 px 程度に）。
2. 書く物：列数（スパン）、段数（階）、窓の形（縦長/横長/帯/無地）、柱型と窓の幅の比、帯・水切り、ガラス張りの範囲、角の作り、足元（ピロティ・基壇・入口）、頂部（笠木・塔屋・設備）、例外（最上階だけ小窓、など）。
3. 一直線の辺（法線差 3° 以内）は `wall_groups` にまとめる。間に入隅の細い辺（1 m 未満）があれば別の面として残し、どの面の続きかを書く。
3b. **階でも部品でもない物**（デッキ・開放廊下・ピロティの天井・面をまたいで折れる通路・大階段）は `structures`：`[{"what","faces":[面 id],"from_photos":[写真 id],"shape":"言葉で（腰壁付き・柱 2 本で支える など）","ratio":"階高・柱間に対する比（例：床は 2 階の床と同じ高さ、出は柱間の 0.4）"}]`。1 m 以上の物は 1 枚にしか写っていなくても書く（設計係が必ず置く）
4. 仮の棟 JSON があれば「仮の設計との食い違い」を必ず書く（面の取り違えはここで見つかる）。
5. 数えられない物は null と理由。寸法（m）は絶対に書かない。

## 出力
`data/reports/<棟id>/kansatsu_<面id>.json` と `data/reports/<棟id>/kansatsu.md`（out/ ではない。git に入り、数え係・設計係が読み、棟 JSON の evidence からこのパスを指す。切り出した画像は out/ のまま）。
## 合格
各面に `source_photos`（id）がある。写真に写っている 1 m 以上の物が全部 `parts` か `structures` にある。null には理由がある。寸法が 1 つも無い。
