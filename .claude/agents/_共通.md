# 係の共通の約束（全係の定義から参照）

- 寸法は `measured`（根拠の写真 id あり）/ `estimated`（方法と根拠あり）/ `unknown`（値 null）のどれか。根拠の無い値は書かない。
- **根拠の門（11/7）**：`measured` の根拠に使う写真は、写真の索引で ①この棟に ②その値の面に（`faces[<id>]` の下・`face` を持つ部品）仕分けられていて、③仕分けの確からしさが `low` なら職員が確かめた（`confirmed_by`）物だけ。外れる写真は `recorder validate` が警告し（`--strict` でエラー）、`recorder photos to-confirm data/buildings/<id>.json` に「確かめてほしい写真」として出る。職員が確かめるまでは、その写真を根拠にした値は `estimated` にする（別の面の写真が要るなら、仕分け係に `faces` を足してもらう）。11/7 の試験で、仕分けの面の外れは全部 `low` だった（`docs/実験_仕分けの正解率_11-07.md`）。
- 決めつけない。見えなければ unknown。仮の幅・なめらかな勾配・平面の当てはめをしない。
- 写真は id（索引 `data/photos/index.json` の `id`）で指す。GPS・方位は目安で、面の確定は目視。
- 出力は必ず JSON ファイル（`data/reports/<棟id>/係名_<対象>.json`）＋短い Markdown の報告。JSON の `made_by` に係名とモデル名、`made_at` に日時。係の報告は out/ ではなく `data/reports/<棟id>/` に書く（out/ は再生成で消え、git にも入らない。棟 JSON の evidence・method はこのパスを指す）。画像（png/jpg）と道具が出す物（`out/<棟id>/landmarks/`・`recheck/`・`coverage_*`・`soten.json`）は今までどおり out/。手順書「係の報告の置き場」。
- 写真は期間中に撮った物だけ（索引は `period: "during"` だけ）。期間前の写真・分類台帳（`D:\名城大学\写真資料_*`）は見ない・根拠にしない（11/7 に決定）。範囲は本部棟・図書館・タワー75・共通講義棟南の 4 棟（敷地 JSON の `scope.targets`）。
- `D:\名城大学` の寸法・座標・完成モデルは値にしない（検算の差を `method` に書くのは可）。Google 由来の物は見ない。
- 道具は `.venv/Scripts/python -I -X utf8 -m recorder …`。Blender は環境変数 `BLENDER`。
- **共有の台帳は道具のコマンドでだけ書く**（11/7）：写真の索引 `data/photos/index.json`（面は `recorder photos set-face`）、登録台帳 `data/photos/registry.json`（`photos register`・`register-chain`・`register-sfm`・`pnp`）、進行役の決定 `data/decisions.json`（`recorder agent decide`）、CC0 の台帳（`recorder assets fetch`）、敷地 JSON。自分のスクリプトで直接書かない。4 棟を同時に回すので、道具が鍵を持って 1 つずつ書く（待つことがある。待ち時間は `out/.locks/waits.jsonl`）。Blender と headless の Edge も道具の中で 1 つずつ順番に走る。
- 分からない事は質問を JSON の `questions` に書いて返す。推測で埋めない。
- 係の中で解決できない事は、自分で決めずに棟 JSON の `requests` に書く：`kind` は `photo`（撮影が要る）/ `tool`（語彙・道具が足りない）/ `asset`（定型の物の見た目が要る）/ `data`（PLATEAU・OSM・標高の食い違い）/ `check`（規則で決まらない争点）。進行役（`shinko`）が `recorder agent events` で拾って決める。待たない（置ける物は置いて先へ進む）。
- 大学・キャンパス固有の名前（棟名と id の対応、既定のキャンパス、地図の在りか）はコードに書かず、敷地 JSON `data/site/<campus>.json`（`aliases`・`scope`・`name_links`・`sources`）に書く。
- 語彙（部品の型）とアセット（CC0 の置物・質感）の追加は進行役の決定（`data/decisions.json`、`recorder agent decide`）が要る。決定 id の無い型・アセットは validate と fetch が拒否する。係は `requests` の `kind: tool / asset` で頼み、待たずに今ある語彙で置く。
