## 3. 職員の画面から敷地を作る道（監査 A 6・9・11・24）
- `POST /api/campus`：`{university, campus_name, slug?, bbox? | address?, osm_relation?}`。**範囲（bbox）か住所が無ければ断る**（原点が天白になるのを防ぐ）。住所は OSM の Nominatim で範囲に（Google は使わない）。日本語の名前だけで slug が作れなければ短い名前（英数字）を求める。既にある slug は作り直さず選ぶだけ。relation は `sources.osm.relation` に書く。`site.campus_init` を呼ぶのは `call_campus_init` の 1 か所。
- 名城の敷地が既にあっても、「別のキャンパスを足す」で新しい敷地を作れる（監査 A 9 の「準備済みと出て名城のまま進む」を避ける道）。
- `POST /api/campus/select`：使う敷地を選ぶ。`RECORDER_CAMPUS` に入れ（係と、係が打つコマンドに渡る）、敷地 JSON が 2 つ以上なら `data/site/default_campus.txt` にも書く。`recorder serve --campus <slug>` も足した。
- `POST /api/site/build`：別スレッドで `recorder site build --campus <slug>` → `recorder site export-web --campus <slug>` を **CLI として** 打つ（形は `site_build_commands` の 1 か所。F1 が site.py の関数・引数を変えても受付は壊れない）。進捗は `/api/progress` の `site`（state・step・最後の 12 行・error）と `/api/site` の `site_run`。画面の 1 段目に「地図と標高を取る」ボタンと記録の窓。
- `/api/site` に `campuses`・`selected`（built＝buildings がある）・`web_matches`（歩く画面の書き出しが選んだ敷地か）・`max_usd_default` を足した。
- **注意（F1 へ）**：`site build` が敷地 JSON の `sources.osm.relation`／`bbox_lonlat` を読む・キャッシュを敷地ごとに分ける（監査 A 1・2・5）は F1 の直し待ち。それまでは、画面から別の大学の敷地を取ると天白の OSM が返る恐れがある。画面には「別の大学で通した試しはまだ無い」と書いてある。
