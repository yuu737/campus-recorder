# F3 写真の id と名前の普遍化（11/8）

担当：recorder/photos.py・photoproj.py・publish.py（鍵の直しだけ）、landmarks・registry・evidence の「短い名前」の所、
tests/test_photos_ids.py（新規）。コミットはしていない。本物の索引 `data/photos/index.json` は書いていない（試しは一時フォルダの写し）。

## 直した事

### 1. 取り込みの id の重なり（監査 A 16、重度）
- id はこれまで通り**ファイル名の幹**（PXL_…・IMG_0001・20261107_150551・日本語名、機種に依らない）。
- 索引に同じ id があれば**中身の sha256 で同じ写真か確かめる**（`photos.resolve_photo_id`）。
  - 同じ写真（別のフォルダから入れ直した物も）→ 同じ記録を更新。人が入れた building / face / notes は残す。
  - 別の写真 → `<幹>_<sha256 の先頭 8 文字>` の id にして分け、記録に `id_collision`（元の幹・相手の file・理由）を残し、標準エラーに 1 行出す。
  - 記録に sha256 が無い前からの記録は、同じ file か、元の写真の sha256 を計算して比べる。元の写真が無い時は撮影日時（秒）・機種・大きさが全部そろう時だけ同じとみなす。
- 新しく入る記録・入れ直した記録には `sha256` を持たせる。**既にある id は変えない**（写しの索引で、既存 408 件が 1 件も変わらないことをテストで確かめた）。

### 2. 短い名前（監査 A 15、重度）
- `photos.short_name(pid)`：Pixel は前と同じ時刻の数字（既にある `lines_f0_070904733.json` 等と合う）、それ以外（IMG_0001・Galaxy の日付・日本語名）は id のまま（ファイル名に使えない文字は `-`、40 バイトを超えたら切って hash の頭を付ける）。
- `photos.short_names(pids)`：同じ短い名前になる写真には全部 sha1 の頭 6 文字を付ける（並び順に依らない）。
- photoproj.py：Blender の視点名・描画の読み戻し・ずらした視点の名前を `short_names` の結果に。`short_id` は表示用に `short_name` を呼ぶだけにした。
- registry.py：`_compare_candidates` の頭の語（IMG・DSC・日付になると別の写真の物を拾う）は日本語の頭の時だけ使う。`_lines_of` は末尾の数字（IMG_0001 → 0001 が DSC_0001 と重なる）でなく `short_name` と id で探す。
- evidence.py `entity_name`：英数字が 1 つも無い日本語名が全部 `photo` になって重なっていたので、その時だけ hash の頭を付ける（既存のテストの形は保った）。
- landmarks.py：同じ短縮は無かった（触っていない）。

### 3. 担当ファイルの残りの重度・中度
- **期間の決まり（監査 A 22）**：`period_of(taken, start)`。start は敷地 JSON の任意の `photo_policy.period_start`（`photos.period_start_of`）。**無ければ期間の決まり無しで全部 during**（他校の手持ちの写真が消えない）。
  名城の `data/site/tempaku.json` に `photo_policy.period_start = 2026-11-02T12:00:00` を足した。CLI の `--period` の説明も直した。
- **磁気偏角（監査 A 21）**：`DECLINATION_DEG = -8.0` の固定をやめ、敷地 JSON の `declination_deg` → 写真の GPS の緯度経度 → 敷地の原点（`crs.origin_lat/lon`）の順に、国土地理院 2020.0 年値の概算式（`photos.declination_gsi`）で出す。名古屋で約 −7.8°、北海道 −9.6°、沖縄 −5.1°。

### 4. 追記分（Fable 11/8）
- **(a) 鍵を持ったまま縮小・顔の検出（監査 B 3、J-012 の再発）**：
  - `photos.patch_index(index_path, diffs)`：鍵を取って索引を読み直し、id ごとの差分だけ書く（registry.save_registry と同じ形）。`masks` は自動（by auto）の箱だけ置き換え、保護係・見直しの箱は今の索引の物を残す。
  - `import_photos`：EXIF・sha256・縮小版（顔の検出）は鍵の外。最後に鍵の中で読み直し、既存の記録は差分、新しい記録は追加（鍵の外にいる間に同じ名前の別の写真が入っていたら接尾辞の id に付け替え、縮小版の名前も合わせる）。
  - `make_sends`（photos send）・`publish.publish`（photos publish）も鍵の外で回し、最後に `patch_index`。
  - `recorder/__main__.py`：`LEDGER_WRITERS` から `("photos", "import")` を外した（関数が自分で鍵を取る）。`run_t4` は send・publish を鍵の外で呼ぶ。`tests/test_registry_lock.py` の「import は全体で鍵」の 1 行を「assign は全体で鍵・import は None」に直した。
- **(b) `photos tape` → `photos ruler-mark`**：`measure tape`（目盛りから周期）と別の仕事なので改名。`photos tape` は残し、標準エラーに「古い名前です」を出して同じ処理に流す。
  - **関数名は変えていない**：serve.py の /api/tape が呼ぶのは今まで通り `photos.mark_tape(...)`。
