## コマンドの使い方
```
# 1. メジャーの読み（係が拡大画像で目で読んだ cm と、またがったタイルの枚数）→ tape の輪
recorder measure tape 本部棟正面柱92cm --read "0→91.0" --n 8 --what tile_pitch_h --building honbu --face f6 --by "測量係 opus"
   → data/reports/honbu/sokuryo_tape_本部棟正面柱92cm.json、続けて棟の周期を突き合わせて sokuryo_tape_pitch.json
# 2. 棟の周期を決めて物差し台帳に（台帳はこの道具でだけ書く）
recorder measure pitch honbu --what tile_pitch_h --write-rulers [--rulers <写し>]
# 3. 正面化した面の周期が一様か（3〜4 か所に分けて px。ばらつき 1 % 以下で uniform_period の輪）
recorder measure uniform <front.jpg> --what tile_pitch_v --photo <写真id> --face f6 --px-range 6 15 --wall-box x0 y0 x1 y1
   → <front>_uniform_<what>.json（--out で変えられる）
# 4. 周期 × 枚数（× px の比）で値と鎖
recorder measure chain honbu --face f6 --key bay_pitch --what tile_pitch_h --count 46 --count-photo PXL_20261103_042900775 \
    --count-what "柱型の芯から芯のタイル枚数" --uniform <uniform.json> [--ratio 180 910 --ratio-photo <id> --ratio-what "…"]
   → data/reports/honbu/sokuryo_chain_f6.json
     values.bay_pitch ＝ 棟 JSON にそのまま写す形（value / unit / tol / status / measured_kind / evidence / method / chain）
     rescale.bay_pitch ＝ 同じ面の前の値（sokuryo_f6.json の bay_pitch、PLATEAU 由来）からの差 %（README の「付け替えで何 % 動いたか」）
     scale.bay_pitch ＝ 周期 m ÷ 周期 px の縮尺（px_per_m）
# 別の棟の周期（その棟にメジャー写真が無い時だけ。申告 claim の輪が入って estimated。メジャーがあれば道具が断る）
recorder measure chain library --face f2 --key … --what tile_pitch_h --pitch-from honbu --count … --count-photo …
```
どれも `--reports <フォルダ>` で書き先を一時フォルダに変えられる。

### measured / estimated の決め方（道具が決める）
- 鎖が `tape`・`count`・`px_ratio`・`uniform_period` だけなら measured。`tape` 1 輪だけなら `measured_kind: direct`、他は `chain`。
- 次は estimated（理由の輪を足す）：メジャーが別の棟（`claim`：同じタイルという申告）、メジャーを当てた面が違う・不明（`assume`）、枚数で広げるのに一様の根拠が無い（`assume`）。
- 一様の根拠は `measure uniform` の輪か、**同じ面の別の場所のメジャー写真**（差が ± の和以内）。後者は `uniform_period` の輪で、`px` の欄に 2 枚のメジャーの周期を mm で入れる（下の質問 2）。

## tol の式（`measure.chain_tol`。T1 の `schema.chain_tol` と同じ式を自分で書いた）
値は輪の積（周期 × 枚数 × 比）なので、輪ごとの相対の ± を**足して**（二乗和にしない）|value| を掛ける。

    chain_tol = |value| × Σ
       tape            輪の tol ÷ 輪の value ＝ (0.005 m ÷ n) ÷ (区間 ÷ n) ＝ 0.005 m ÷ 区間
       count           tol ÷ n（tol 既定 ±1 枚）→ ±1 枚 × 周期
       px_ratio        px_tol ÷ a + px_tol ÷ b（px = [a, b]、px_tol 既定 1 px）
       uniform_period  (最大 − 最小) ÷ 2 ÷ 平均（か所ごとの周期のばらつきの半幅）
       それ以外の輪    0（estimated の鎖だけ）

- 周期の ± は「両端 ±0.5 cm ÷ 枚数」を、第 1 部の例（`0→91.0`・n 4 → tol 0.00125）に合わせて **0.005 m ÷ n**（両端あわせて ±0.5 cm）とした。
- 書く tol は 0.1 mm 単位で切り上げ（丸めで鎖の ± より狭くならない）。周期の輪の tol は 1 µm 単位で切り上げ。
- T1 の `schema.py` が出てから突き合わせた：`tests/test_measure_chain.py::test_matches_the_checker_in_schema_if_present` で、道具の出す 4 通りの値（direct・4 輪の chain・2 枚目のメジャーで一様・別の棟）について `schema.chain_tol` と 0.1 % 以内で一致し、`schema.chain_problems` が 0 件。

## 質問（Fable へ）
1. **閾値 1 % と正面化の歪み**：本部棟 f6 の柱型の縦の周期が上から下へ 2 % 動く。正面化の縦の歪みなら、uniform_period は「正面化を直してから」か「高さの区間ごとに輪を分ける」必要がある。閾値を上げる（例 2 %）のは、± にばらつきの半分が積まれるので数の上では正直だが、「一様」の言い方と合わなくなる。どうするか。
2. **2 枚目のメジャーで一様の代わり**：T1 の検証は `uniform_period` の輪に `px`（正の数 2 つ以上）を求めるので、2 枚のメジャーの周期を **mm で `px` の欄に**入れ、`px_unit` に断り書きを付けた（比だけ使うので式は同じ）。欄の名前を分ける（例 `values`）なら T1 と揃える必要がある。
3. **tape の ±**：第 1 部の文「両端 ±0.5 cm ÷ 枚数」は両端を足すと 1 cm にも読めるが、例の tol（0.00125 = 0.005 ÷ 4）と T1 に合わせて「両端あわせて ±0.5 cm」にした。両端それぞれ ±0.5 cm（計 1 cm）にするなら、`TAPE_END_M` を 0.01 に変えるだけ（T1 側も同じく）。
4. **前の値との差の鍵**：`rescale` は `sokuryo_<面>.json` の同じ名前の鍵（`bay_pitch`・`floor_pitch` など）を前の値と見る。棟 JSON の値と比べたい時は、どの値（面・部品の場所）を前の値にするかを決めてほしい。

## 追記（11/8、Fable の答えと追加の決定を入れた）
1. **一様の閾値 1 % → 3 %**（`UNIFORM_THR = 0.03`）。3 % 以内なら輪を出し、ばらつきの半幅 ÷ 平均は今の式どおり ± に入る。
   か所ごとの周期が一方向に（単調に）変わる時は、`measure uniform` の出力と輪に `"drift": {"direction", "percent"}` と `note`「正面化の歪みの疑い…検収係が見る」を書く。正面化は直していない。
   本物で再試行：本部棟 f6 の南西の柱型の縦（stitched、x 680〜790・y 600〜3400）は 9.46・9.38・9.34・9.27 px、ばらつき 2.03 % → **輪が出た**。drift は「上から下へ小さくなる −2.01 %」。仮の縦の周期 0.07 m・59 段で鎖を組むと 4.13 m ± 0.149 m（measured・chain）。T1 の `chain_problems` は 0 件。
2. **2 枚目のメジャーを一様の根拠にする時**：`px` に 2 枚の周期を mm、`px_unit: "mm"`。T1 の検証は px_unit を "px" か "mm" ちょうどで読むので、断り書きは px_unit から外してコードのコメントに移した。T1 の検証を通ることをテストで確かめた。
3. tape の ± は変えていない（両端あわせて 0.005 m ÷ 区間）。
4. **rescale の前の値**：`data/buildings/<棟>.json`（読むだけ）の同じ面・同じ鍵の今の値を優先し、無ければ `sokuryo_<面>.json`。どちらを使ったかを `rescale.<key>.baseline` に `building_json` か `sokuryo_json` で書く。鍵は面の中の点区切り（`bays.pitch`・`length`・`top_z`）か別名（`bay_pitch` → `bays.pitch`、`pier_width` → `bays.pier_width`）で、面に無い `floor_pitch` は棟の上の段の同じ鍵。`--buildings <フォルダ>` で読む先を変えられる（テストは写し）。
5. **`--count-photo2 <id>`**（追加の決定）：2 枚目の写真で同じ枚数を数えた時に count の輪へ `"confirmed_by": "<id>"` を書く。その輪の相対の誤差は 0 になり、2 枚目の id は evidence にも入る。`--count-photo` と同じ id は道具が断る（終了コード 2、`build_chain` は ValueError）。T1 の検証と同じ規則で、テストで `chain_problems` 0 件を確かめた。
   `sokuryo.md` の手順に足した 1 行：「枚数は別の写真でもう一度数え、一致したら `--count-photo2` に書く。一致しなければ数え直し、それでも違えば少ない方の枚数で ±1」。

テスト：`tests/test_measure_chain.py` 15 件・`test_measure_tape.py` 3 件・`test_measure_period.py` 5 件、計 23 件が通った。追記の分の所要 約 20 分。

## 追記 3（11/8、横のメジャー → 同じ正面化画像の px の比 → 縦の周期）
**結果：本部棟 f6 の縦の周期 = 0.06771 m ± 0.0014 m（measured・chain、±2.1 %）**。出力は一時フォルダだけ（本物の reports・棟 JSON・台帳は書いていない）。
- 横（tape）：測量係の読み `本部棟正面柱92cm` 5.4→86.2 cm ÷ 7 枚 = 0.115429 m。± は決めたとおり 0.005 m ÷ 区間で 0.000715 m。測量係の書き方（1.0 cm ÷ 7 = 0.0014 m）なら、縦の ± は 0.0018 m（±2.6 %）になる。
- 画像：1 枚の正面化画像 `out/rectified/honbu_roi/PXL_20261103_042900775_front.jpg`。stitched と同じ座標だが、2 枚をつないだ画像ではなく写真 1 枚。
- 横：4 階の窓の下の帯（x 1000〜4400、y 1000〜1110）。1 行ずつの自己相関の 100 番目の山で、**横 100 枚 = 1599.62 px**（1 枚 15.99 px）。4 か所で 15.99・16.07・16.00・15.99 px、ばらつき 0.50 %、drift なし。
  列ごとに足した並びだと馬踏みのせいで 8.0 px（半分）に出るので、1 行ずつ自己相関を取って平均する道具を足した（`uniform_period(rowwise=True)`）。
- 縦：南西の角の柱型（x 680〜790、y 600〜3400）。1 列ずつの自己相関の 100 番目の山で、**縦 100 段 = 938.38 px**（1 段 9.38 px）。4 か所で 9.46・9.38・9.34・9.27 px、ばらつき 2.03 %。**drift：上から下へ小さくなる −2.01 %**（正面化の歪みの疑い）。
- 鎖：tape → uniform_period（横）→ uniform_period（縦、drift 付き）→ count 100 枚 → count 100 段 → px_ratio [938.38, 1599.62]。
  - 値 = 0.115429 × 938.38 ÷ 1599.62 × 100/100。
  - ± の内訳：tape 0.62 %、横の一様 0.25 %、縦の一様 1.01 %、px_ratio 0.17 %、合計 2.05 %。
  - count の tol は 0。枚数は自己相関の 100 番目の山なので数え違いが無い、という扱い。周期の取り違えは一様の輪と近接の読みで確かめる。
  - 縦の count は割る側なので `role: divide` を付けた。T1 の chain_tol は相対の足し算なので式は変わらない。T1 の検証（chain_problems）は 0 件。
- **近接の縦の読みとの差**：本部棟縦 6.80 cm に対し −0.42 %、PXL_20261107_061640829 の 6.65 cm に対し +1.83 %。どちらも ± の中（近接の読みは ±1.0 cm・1 段で、面は low）。
- 道具：`recorder measure chain <棟> --face <面> --key tile_pitch_v --what tile_pitch_v --ratio-from-h <front.jpg> --photo <写真id> --h-box x0 y0 x1 y1 --v-box x0 y0 x1 y1 [--px-range 6 40]`。`scale.tile_pitch_v` に横・縦の箱、か所ごとの px、ばらつき、drift、またがった長さが残る。`sokuryo.md` に 2 行足した。
- 仮定（質問）：px の比は、正面化が縦横の比を保つ（縮尺が縦と横で同じ）ことを前提にしている。縦の drift −2 % があるので、帯と柱型の高さの違いで比が最大 1 % ほど動きうる（± の縦の一様 1.01 % に入っている）。
