読み：
- 69.5 m の箱は **タワー75 の輪郭の外**（西面 f2・f3 の外に接する別の多角形）。tower75 の観察・設計の記録は「塔の高さに当たる値が塔の足元の外の部品（普通無壁舎）に付いている」と書いており、塔の一部か、PLATEAU の高さの付け違いかは写真で決まっていない。
- 24.2 m の箱は **甲板と通路橋の OSM 多角形そのもの**（library の観察票 kansatsu_f1・f2 の記述と一致）。どちらの棟の輪郭にも入らず、敷地の物に置き換わっているのは通路橋の部分（16.7 %）だけ。残りの約 528 m² の甲板はまだ敷地の物に無い。

→ どちらも 70 % に届かないので **結び付けず、`replaced_by` も付けていない**。撮影依頼を敷地 JSON の `requests` に 2 件書いた（敷地の検収係 shikichi の形：`status` open・`action` request・`fix_in` site・重なりの数・依頼の文）。
- `plateau-f693ff16-tower75`：タワー75 の西面 f2・f3 の外に何が立っているか（柱・庇・吹き抜けの枠か別の低い物か）を、西の通路から足元から頂部まで 2 枚以上。塔と同じ高さなら設計係が塔の塊として足す、低ければ進行役が箱を外す判断。
- `plateau-2e2a316f-bridge-library-tower75`：図書館の北西の甲板を敷地の物 deck として起こす写真（上から縁の角と床の高さ、下から庇・柱の高さ、各 2 枚）。甲板が起きれば箱を `replaced_by` で外せる。

## 2. 道具（recorder/site.py・recorder/__main__.py）
`recorder site link-box <棟|敷地の物> <箱id> --why 理由 [--ask 撮影依頼の文]` を足した（鍵 ledger の対象）。
- 箱 id は先頭の一部でよい（`bldg_f693ff16`）。相手が `objects` の id なら敷地の物、それ以外は棟 JSON の棟。
- 70 %（`site.PLATEAU_LINK_MIN`）以上：棟なら `plateau_parts` へ移し（前に持っていた OSM の棟から外す）、根拠（重なりの割合・理由・誰・いつ）を棟の `confirmation.plateau_links` と敷地 JSON の `plateau_links` に残す。敷地の物なら `plateau_links` に `kind: replaced`・`replaced_by: <object id>` を書く。
- 70 % 未満：結ばず、`requests` に撮影依頼（同じ id は上書き、重ねない）。
- `site build` で作り直しても `plateau_links` を当て直す（`apply_plateau_links`）。`site export-web` は `replaced_by` の箱を描かない（`replaced_boxes`）。
- テスト `tests/test_link_box.py`（新規 4 件）：輪郭の中の箱を結ぶ・半分の重なりは依頼だけ（重ねない）・敷地の物に置き換え＋作り直しで消えない・知らない箱や棟は誤り。
