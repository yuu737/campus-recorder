## API

- `/api/steps`：工程の順は `agents.PIPELINE_STEPS`（＋`CONTINUE_STEPS`）、係の名前と一言は `.claude/agents/*.md` の description を「。」の前後で分けた物、モデルは frontmatter（`agents.load_agent_defs`）。コードの工程（seizu・seizu_final・web）は「製図・模型係（コード）」
- `/api/pipeline`：`data/reports/<棟>/pipeline_*.json` と `out/<棟>/pipeline_*.json` の最新（`pipeline_state.json` の `record_name` があればそれ）の工程ごとの 工程・係・モデル・秒・費用・要約 1 行（note → summary → stop → error、140 字）と、`out/<棟>/pipeline_state.json` の status・current・done・stopped・spent_usd・max_usd、このサーバが起動した物の状態
- `/api/artifacts`（指示に無かったが足した）：serve は `data/reports/`・`data/buildings/` を配信しないので、場面に要る生成物の一覧と数を 1 回で返す。在るファイルだけを `/out/…`・`/data/photos/…` の道で返す（ページ側でも `onerror` で消す）

## できなかった事・気になった事

1. **製図板と正面化の絵には、元の写真の垂れ幕（掲示物）がそのまま写る。** `coverage_<面>_photo.png`・`out/rectified/…_front.jpg`・`recheck/…/lines_*.png`・`view_photo_*` の元は元の写真で、灰色の箱（send_file に塗った物）は効いていない。本部棟の f6 の祝いの垂れ幕が c・f・g の絵に大きく出る。規約 4 の「貼り紙・掲示物は撮らない。写っていれば提出物から外す」に当たるかは利用者の判断が要る（写真の場面 a・b は send_file なので箱が付いている）
2. 生きている時の絵は撮っていない状態の確かめだけ（本部棟は `pipeline_state.json` が無く、「記録はまだ動いていません」と 11/7 の記録の一言が出る）。止まった帯は API のテストでだけ確かめ、画面では見ていない
3. d の「推定 → 実測に変わった値の強調」は、生きている時に数が変わった行を光らせるだけ。値ごとの前後（method の「前 … → …」）は読んでいない。本部棟は鎖のある measured が 0 件なので、鎖の小さな図は tape_select の読みで代わりに出している（台帳への書き込み前と明記）
4. g の「写真と模型が合う瞬間」は view_photo と写真を半透明に重ねるだけ。photoproj の overlay は本部棟の最新の photoproj の対象と合格の面の写真が重ならず、使っていない（在れば一覧に入る）
5. 再生の経過・費用は記録の値（本部棟の記録は subagent で回した物なので費用は「記録なし」）
6. 写真の場面の灰色の箱は本部棟で 155 個（保護係の掲示物の箱が多い）。札が重なって読みにくい所がある

## 追記（11/8、利用者の決定「案どおり」と Fable の追記 2）

### 元の写真から作った絵にも灰色の箱
- 見た目は `privacy.paint_masks` と同じ：#8a8a8a の塗り、縁は濃い灰（#282828）で画面の 2 px、札は左上の濃い帯に白い文字で、文字の高さは絵の高さの 2 %（画面で 9 px より小さくはしない）。描くのは SVG の重ね（`progress.js` の `maskGroup`・`overlayMasks`）
- **by: auto のまま（見直しで確かめていない）の顔の箱は描かない**（F11 の決まり。`serve._shown_masks`）。写真の場面 a・b も同じ
- 写真と同じ枠の絵（縮小版・検収の重ね `lines_*.png`・模型の描画 `view_photo_*.png`）：box の割合をそのまま当てる
- 正面化した絵（場面 c）：`out/rectified/<…>/<id>_front.json` の H（写真 px → 正面化した絵 px。`pose.py` と同じ使い方）で箱の四隅を写した多角形。箱のうち地平線の向こう（平面に乗らない所）は切り捨てる。H の無い正面化の絵は見せない（`masks_ok: false`。箱を写せた物を先に選ぶ）。本部棟の 7 枚は全部写せた
- 製図板（場面 f）：coverage.json には写真ごとの H が無いので、登録（`data/photos/registry.json`）の面ごとの H_plane から `coverage.entry_H_now` の逆（写真 px → 面の (s, z)）で写した。手前・向こうの判定は、その写真の使える所の中心を基準にする。**箱のある写真の 1 枚でも写せなければ、その面は見せない**。本部棟の f6 は、coverage を作った後に登録から外された 3 枚（042822099・042830256・042844361、検収係の「柱割り 4 つ分ずれた登録」）の画素が製図板に残っていて H が無いので見せず、f8（箱 18）を使った。箱は写真を開くたびに、その写真の使える所の中だけに出る
- 証拠ビューア（場面 h）：写真の区画の位置が決まっていないので箱を写せない。模型と視点の絵（evidence_three）を大きく、写真の区画の絵（evidence_photo）は右下に小さく（幅 22 %）した。**残り**：evidence_three の右上にも写真の小さな区画があり、箱は付いていない
- 箱の元は索引の masks だけ。保護係・見直しが指していない掲示物は塗れない（例：本部棟の 042734715 の垂れ幕は見直しの箱「垂れ幕の塗り残し」で覆われた）
